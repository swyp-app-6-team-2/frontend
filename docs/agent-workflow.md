# 멀티 에이전트 워크플로우 — 별따먹자 적용 가이드

> 출처: YouTube [Uzchowall] "AI 활용의 정점 — 에이전트 워크플로우" (woSiT_kytXo)
> 영상의 워크플로우 설계를 **이 저장소의 실제 도구**(Claude Code `Workflow` 도구 · `seunghwan-harness` 에이전트 · `CLAUDE.md`/`context.md`/`MEMORY.md`)로 번역한 실행 지침.

**한 줄 요약** — 사람은 **마스터 AI 하나와만 대화**하고, 마스터가 `기획 → 개발 → QA → 위키` 4단계를 굴린다. 각 단계는 **작업자 AI + 검수자 AI(다른 모델·읽기전용)** 쌍으로 돌아가고, 모든 "완료"는 **증거로 검증**되며, 통과할 때까지 반복한다.

---

## 1. 전체 구조

```
                 ┌─────────────────────────────────────────────┐
 사람 ◀────────▶ │  마스터 AI  (오케스트레이터)                  │
 (마스터와만 대화) │  · 요구사항 → 명세표(범위/비범위)             │
                 │  · 단계별 모델 선택 · 병렬 분할 · 권한/재개 관리 │
                 └───────┬───────────┬───────────┬─────────────┘
                         ▼           ▼           ▼
                   ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
                   │  기획   │▶│  개발   │▶│   QA    │▶│  위키   │
                   │ Plan    │ │ Dev     │ │ (테스트)│ │ Docs    │
                   └────┬────┘ └────┬────┘ └────┬────┘ └────┬────┘
        각 단계:        │           │           │           │
   작업자 ↔ 검수자   [작업자][검수] [작업자][검수] [작업자][검수] [작업자][검수]
   (통과까지 반복)      승인될 때까지 loop · 2~3회 반복 시 마스터로 에스컬레이션
```

- **입력**: 마스터가 대화로 요구사항을 뽑아 **명세표**(구현할 것 + *구현하지 않을 범위 외* 목록)를 만든다.
- **기획**: 명세표 → **TODO 리스트** + **QA 테스트 리스트**로 분해.
- **개발**: 개발 AI는 **TODO 리스트만** 보고 구현(다른 문서 안 봄). 항목마다 체크 + **완료 근거** 명시.
- **QA**: QA AI는 **테스트 리스트만** 보고 실제 조작(버튼 클릭·입력·공격적 입력) → **스크린샷 증거** 캡처 → 보고.
- **위키**: 큰 그림/구조만 MD로 요약 기록(코드 세부는 안 씀 — 코드 자체가 맥락). 다음 작업의 참고 소스.

## 2. 핵심 원칙 12가지 (원칙 → 왜 → 별따먹자 적용)

### ① 사람은 마스터 AI 하나와만 대화한다
- **왜**: 진행/오류수정/위임을 사람이 손으로 안 하고 오케스트레이터에 위임 → 사람은 의사결정만.
- **적용**: Claude Code 메인 루프가 마스터. 큰 작업은 `Workflow` 도구로 파이프라인을 짜서 던지고, 결과 요약만 받는다. 세부 로그는 컨텍스트에 안 쌓임.

### ② 작업자와 검수자를 분리하고, **서로 다른 모델**을 쓴다
- **왜**: 같은 모델의 자기검수는 약하다. "코덱스가 짠 걸 클로드가 리뷰하면 잘 잡는다" — 교차검증이 핵심.
- **적용**: `Workflow`의 `agent()`에 `model` 오버라이드로 작업자/검수자 모델을 다르게. 예: 구현은 `opus`, 검수는 `sonnet`(또는 반대). 자기 코드 자기 리뷰 금지.

### ③ 검수자는 **읽기 전용**. 절대 직접 수정하지 않는다
- **왜**: 검수자가 손대면 작업자 모델의 스타일·시퀀스가 꼬인다. 검수자는 *훈수만* 두고, 작업자가 고친다.
- **적용**: `seunghwan-harness`의 `qa`·`code-reviewer`·`reviewer`·`security`·`perf` 에이전트는 이미 **Read/Glob/Grep 전용**(쓰기 도구 없음) → 이 원칙에 정확히 부합. 검수는 이 에이전트들로, 수정은 별도 구현 에이전트로.

### ④ **증거 기반 완료** — "구라치지 말고 근거를 대라"
- **왜**: 환각으로 "완료" 처리하는 걸 막는다. 체크하려면 **무조건 근거**(무엇을·어디를 바꿨는지) 명시.
- **적용**: 구현 에이전트의 출력 `schema`에 `changes: [{file, line, evidence}]` 필드를 강제. 검수 에이전트는 그 근거를 **실제 코드와 대조**해 승인/반려.

### ⑤ 명세표에 **"하지 않을 것(범위 외)"**을 명시한다
- **왜**: 스코프 크립 방지. 개발 AI가 딴 데 손 안 대게.
- **적용**: 마스터 단계에서 `구현할 것` / `이번에 안 할 것` 두 리스트를 만들어 TODO에 박는다. (`task.md` 컨벤션과 결합)

### ⑥ 각 에이전트는 **자기 리스트만** 본다 (좁은 스코프)
- **왜**: 개발 AI는 TODO만, QA는 테스트 리스트만 → 맥락 오염·비용 감소.
- **적용**: `pipeline()` 스테이지마다 프롬프트에 **그 스테이지 입력만** 전달. 전체 컨텍스트를 매 에이전트에 붓지 않는다.

### ⑦ QA는 실제로 **조작하고 스크린샷을 남긴다**
- **왜**: "테스트했다"는 말이 아니라 증거. 공격적 입력(특수문자·새로고침 연타)도 포함.
- **적용**: 이 저장소의 검증 방식 그대로 — `xcrun simctl openurl` / `adb shell` 로 화면 이동 후 `simctl io … screenshot` · `adb exec-out screencap`. 캡처를 QA 에이전트 결과로 첨부. (이미 이 세션에서 쓰던 패턴)

### ⑧ **승인될 때까지 반복** + 무한루프 안전장치
- **왜**: 검수자가 반박이 없을 때까지 loop. 단, 같은 주제가 2~3회 반복되면 마스터로 에스컬레이션.
- **적용**: `Workflow`의 loop-until-dry 패턴 + `한 항목 재시도 N회 초과 → 사람/마스터에게 보고`. `budget`으로 상한도 건다.

### ⑨ QA 실패 → **자동 롤백 후 재작업**
- **왜**: QA fail이면 TODO·개발을 다시. 통과할 때까지.
- **적용**: 스테이지가 throw하면 그 항목을 되돌리고(작업 브랜치/worktree) 재-파이프라인. `isolation: 'worktree'`로 병렬 재작업 충돌 방지.

### ⑩ 권한 부족 → 마스터 호출, 토큰 리셋 → 예약 재개
- **왜**: 서브 에이전트가 막히면 마스터에게 권한 요청 후 재개. 완전 자동화.
- **적용**: 서브 에이전트가 막히면 결과에 `blocked: {reason}`을 실어 반환 → 마스터(메인 루프)가 판단. 긴 대기(토큰 리셋·CI)는 `ScheduleWakeup`/`CronCreate`로 그 시점 재개.

### ⑪ **위키 = 큰 그림만**, 코드 세부는 안 쓴다
- **왜**: 코드 자체가 맥락. 위키는 인덱스처럼 "아키텍처·모델정책" 큰 구조만. 과한 RAG는 오버엔지니어링.
- **적용**: **이미 있다** — `CLAUDE.md`(규칙)·`context.md`(구조/현황)·`spec.md`·`task.md`·`MEMORY.md`(항목 인덱스). 작업 후 여기에 **요약만** 갱신. 코드 주석은 "AI 노트"로 최소한.

### ⑫ 단계별 **모델을 마스터가 선택** (비용이 진짜 제약)
- **왜**: 이 워크플로우의 유일한 치명적 단점은 **비용**. 기획·개발·QA·위키에 각각 맞는 크기의 모델을 배정.
- **적용**: `Workflow` `phase`/`agent`의 `model`·`effort`로 스테이지별 배정. 기계적 단계는 `haiku`/`low`, 어려운 검수만 `opus`/`high`. 사람이 아니라 스크립트(=마스터)가 배정.

### (보너스) 포크드 세션으로 **공유 맥락 1회 로드 후 분기**
- **왜**: 위키+코드+명세를 한 번 읽어 맥락을 만든 뒤, 작업자-시드/검수자-시드로 **fork** → 캐시 히트율↑(개발 ~90%, 기획 ~85%) → 비용↓.
- **적용**: `Workflow`의 `subagent_type: "fork"`(부모 컨텍스트 상속) 또는 공용 컨텍스트를 한 번 만들어 여러 `agent()`에 전달. 프롬프트 캐시(5분 TTL) 고려해 스테이지 간격 관리.

### (보너스) 큰 작업은 **병렬 분할 후 합쳐서 재검증**
- **왜**: 일감이 크면 마스터가 A·B·C로 쪼개 동시 실행 → 끝나면 셋을 합쳐 한 번 더 검증.
- **적용**: `parallel()`/`pipeline()`로 분할, 마지막에 **통합 검증 스테이지** 1개(배리어). 이 저장소 화면 단위(파일별)로 자연스럽게 병렬화 가능.

## 3. 별따먹자 매핑 표

| 영상 개념 | 이 저장소에서 | 상태 |
|---|---|---|
| 마스터 AI | Claude Code 메인 루프 + `Workflow` 오케스트레이터 | ✅ 있음 |
| 기획 단계 | `pm` → `architect` / `frontend`·`backend`(계획만) | ✅ 에이전트 존재 |
| 개발 단계 | 구현용 `agent()`(쓰기 도구 有) | ⚠️ 구현 에이전트는 인라인 |
| QA 단계 | `qa` 에이전트 + `simctl`/`adb` 스크린샷 | ✅ 패턴 확립됨 |
| 검수자(읽기전용) | `code-reviewer`·`reviewer`·`security`·`perf`(Read/Glob/Grep) | ✅ 정확히 부합 |
| 위키 | `CLAUDE.md`·`context.md`·`spec.md`·`task.md`·`MEMORY.md` | ✅ 이미 운영 중 |
| 명세표(범위/비범위) | `task.md` + 워크플로 입력 스키마 | ⚠️ 비범위 명시 습관화 필요 |
| 단계별 모델 배정 | `Workflow` `model`/`effort` 오버라이드 | ✅ 지원 |
| 증거 기반 완료 | `agent()` `schema`의 evidence 필드 | ⚠️ 스키마에 추가 필요 |
| 병렬 분할 | `parallel()`/`pipeline()` | ✅ 지원 |
| 포크드 세션 | `subagent_type: "fork"` | ✅ 지원 |
| 로그/추적 | `Workflow` journal.jsonl | ✅ 자동 |
| 예약 재개 | `ScheduleWakeup`/`CronCreate` | ✅ 지원 |

**결론**: 개념의 90%가 이미 도구/문서로 존재한다. 새로 만들 게 아니라 **조립**하면 된다.

## 4. 바로 쓸 수 있는 워크플로우 스켈레톤

`Workflow` 도구에 넘길 스크립트 골격. 각 단계 = 작업자 → 교차모델 검수 → 승인까지 반복.

```js
export const meta = {
  name: 'feature-pipeline',
  description: '기획→개발→QA→위키. 단계마다 교차모델 검수(읽기전용)로 승인까지 반복',
  phases: [{ title: '기획' }, { title: '개발' }, { title: 'QA' }, { title: '위키' }],
}

const spec = args // 마스터가 만든 명세표: { 구현할것[], 비범위[] }

// 각 단계: 작업자(쓰기 모델) → 검수자(다른 모델·읽기전용) 승인까지 반복
async function stage(phase, workerPrompt, reviewerPrompt, workerModel, reviewerModel) {
  for (let i = 0; i < 4; i++) {                       // ⑧ 무한루프 방지: 상한 4회
    const work = await agent(workerPrompt, {
      phase, model: workerModel,
      schema: { /* changes:[{file,line,evidence}] 강제 → ④ 증거 기반 */ },
    })
    const review = await agent(`${reviewerPrompt}\n대상:\n${JSON.stringify(work)}`, {
      phase, model: reviewerModel, agentType: 'code-reviewer',  // ③ 읽기전용
      schema: { /* approved:boolean, objections:[] */ },
    })
    if (review.approved) return work
    workerPrompt += `\n검수 반려:\n${JSON.stringify(review.objections)}`  // 되던져 재작업
  }
  log('⚠️ 4회 반복 초과 → 마스터 에스컬레이션')                 // ⑧ 안전장치
  return null
}

phase('기획')
const plan = await stage('기획',
  `명세표를 TODO 리스트 + QA 테스트 리스트로 분해. 비범위 준수:\n${JSON.stringify(spec)}`,
  `TODO/테스트 리스트가 명세를 빠짐없이/범위 내로 담았는지 검수`, 'opus', 'sonnet')

phase('개발')
const dev = await stage('개발',
  `이 TODO만 보고 구현. 항목마다 완료 근거(파일:라인) 명시:\n${JSON.stringify(plan)}`,
  `근거를 실제 코드와 대조. 구라 잡아내기`, 'opus', 'sonnet')

phase('QA')  // ⑦ 실제 조작 + 스크린샷은 별도(simctl/adb) — 에이전트가 캡처 경로 반환
const qa = await stage('QA',
  `테스트 리스트를 실기/시뮬에서 조작하고 스크린샷 경로를 evidence로`,
  `스크린샷 증거로 통과 판정. 실패 시 롤백 지시`, 'sonnet', 'opus')

phase('위키')  // ⑪ 큰 그림만
await stage('위키',
  `context.md/MEMORY.md에 이번 변경의 구조·결정만 요약 갱신(코드 세부 금지)`,
  `위키가 큰 그림만 담고 과하지 않은지 검수`, 'haiku', 'sonnet')  // ⑫ 저비용 모델

return { plan, dev, qa }
```

> 이 스크립트는 `Workflow` 도구에 `script`로 인라인 전달. 실제 파일 수정(개발 단계)은 쓰기 도구를 가진 구현 에이전트가 맡고, 검수는 `code-reviewer`(읽기전용)가 맡는다.

## 5. 지금 프로젝트에 도입할 우선순위

1. **증거 기반 완료 습관** — 구현 결과에 항상 `변경 파일:라인 + 근거`. (스키마/프롬프트에 박기) — *가장 값싸고 효과 큼*
2. **교차모델 검수** — 자기 코드 자기 리뷰 금지. 구현과 다른 모델로 `code-reviewer` 검수.
3. **명세표에 "비범위" 명시** — `task.md`에 "이번에 안 할 것"을 항상 적어 스코프 크립 차단.
4. **QA 스크린샷 증거화** — 이미 하는 `simctl/adb` 캡처를 QA 단계의 필수 산출물로 고정.
5. **단계별 모델·effort 배정** — 기계적 단계는 저비용, 어려운 검수만 고비용. (비용이 유일한 병목)
6. **위키 갱신 루틴** — 작업 종료 시 `context.md`/`MEMORY.md`에 큰 그림만 요약. (이미 컨벤션 존재)

> 핵심 철학(영상): "별거 아니다. 사람이 회사에서 기획·개발·QA·문서로 나눠 하던 걸 그대로 AI로 치환했을 뿐." 이 저장소는 그 치환에 필요한 조각(Workflow 도구·읽기전용 검수 에이전트·문서 위키)을 **이미 다 갖고 있다.**
